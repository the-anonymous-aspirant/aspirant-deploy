- `lake-skeleton.sh promote --dry-run` no longer says a refused run "is in the
  ledger as failed": a dry run writes no ledger row, and the refusal now says
  so. A real run's refusal still names its ledger row. The round-trip test
  pins both.
- `docs/data-lake-design/STAGING_PROMOTION.md` "Running it" gives the form an
  operator types for a staged `high` upload: the `read -rs` subshell with
  `LAKE_KEK_FINGERPRINT`, as for `explorer-decrypt-up`. It says that the key
  reaches the container only as a tmpfs file (`stage_real_kek`), and that
  without the fingerprint a mistyped key is accepted. "What this subtask did NOT
  do" no longer says the uploader is unbuilt.
