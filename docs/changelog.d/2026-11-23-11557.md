- Gmail: a pull can fetch attachment content, off unless asked
  (`--attachments`, system_3 #11557, under security's c75385 and c75393).
  Each part is stored under its sha256, never its file name, at sensitivity
  `high`, with Gmail's declared type normalised as the explorer normalises a
  stored one. A part over 25 MB, or whose length differs from its reported
  size, is refused by id and reason. Before any fetch the pull prints its
  estimate and exits 8 if the staging disk cannot hold it. A new
  `gmail_linker` catalog role, which can only insert into the new
  `gmail_attachment_links (message_id, part_id, sha256)`, records which
  message each blob came from, after the ingest succeeds. `verify` proves
  that role's bounds by attempt. `docs/GMAIL_INGEST.md`, "Attachment content";
  `docs/LAKE_SKELETON.md`, "The Gmail attachment linker".
