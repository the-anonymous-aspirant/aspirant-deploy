- Document `SMOKE_USER_ID` in `.env.example` (system_3 #10497).
  - **Why.** `#10490-A1`'s `Source` classification on `proxy_request_log` only tags a call `source=smoke` when it comes from the configured smoke account's user id — deliberately no hardcoded default (security ruling c64784 on #10494), so it fails closed to "not smoke" rather than risk matching the wrong account. Nobody had actually set it: the live cell ran with `SMOKE_USER_ID` unset for the week since #10490-A1 shipped, so every real smoke-sweep call (`scripts/post-deploy-smoke.sh`, user 14 `smoke_valuation`) was silently misclassified as real member traffic instead. Found while validating #10490 end to end (#10497), fixed live on the cell (`.env` + a `server` recreate, not committed here — `.env` is git-ignored).
  - **What this PR does.** Documents the variable in `.env.example` so a fresh deploy, or anyone auditing config drift, sees it's expected to be set — the fix itself (setting the real value) already landed directly on the cell, since `.env` carries no code.
