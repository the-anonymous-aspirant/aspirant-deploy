- explorer: decrypt-on-read can be turned on with the lake KEK (system_3
  #10777, #8806-E0; security c64754 on #8814; operator c64715 on #8813).
  - New `scripts/lake-skeleton.sh explorer-decrypt-up` stages `LAKE_KEK_HEX`
    exactly as `ingest` does: a 0600 file on tmpfs, `LAKE_KEK_HEX` unset,
    and the file deleted on exit. It refuses without the key or the ceremony
    fingerprint. It then recreates `explorer-api` alone with `--wait`, so
    the file is deleted only after the explorer has loaded the key.
  - `explorer-api` in `docker-compose.yml` sets `LAKE_ENVELOPE_DECRYPT` and
    `LAKE_KEK_FILE` only when a key file is staged, and mounts it read-only
    at `/run/secrets/lake_kek`. It never sets `LAKE_KEK_HEX`. With nothing
    staged, it boots as before: decrypt off, `sensitivity=high` contents
    refused. Any recreate without the verb, an auto-pull included, brings it
    back that way.
  - The `lake` and `explorer_api` network comments record the re-derivation
    for an explorer that holds the key.
  - New `tests/lake_skeleton_explorer_decrypt_unit.sh` (23 checks, two
    negative controls). `docs/LAKE_SKELETON.md` documents the verb.
