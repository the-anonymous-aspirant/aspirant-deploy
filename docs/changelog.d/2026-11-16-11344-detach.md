- `scripts/gmail/gmail_pull_and_ingest.sh --detach` runs a pull and ingest as
  a systemd user unit that outlives the SSH session, after asking for the KEK
  in the foreground. Only a hand-off file's path is in the unit, and the unit
  deletes the file as its first act. The KEK is no longer in any process's
  environment, detached or attended: the wrapper hands it to each child on
  fd 3, `gmail.sh` gives it to the container on stdin instead of a tmpfs file
  held for the run, and `lake-skeleton.sh` reads it from `LAKE_KEK_FILE`
  (system_3 #11344; security c70261). `docs/GMAIL_INGEST.md` "Where the KEK is
  during a run".
