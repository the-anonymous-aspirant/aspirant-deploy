- Lake: what waits in the staging bucket is listed in the catalog, so the
  explorer can show an upload before it is promoted (system_3 #11615). `up`
  issues a key that can only read staging and a catalog role that can only
  write two new tables, `staged_uploads` and `staged_uploads_read`, which
  the catalog owner creates. `lake-skeleton.sh list-staged` reads the listing
  and each upload's manifest, never a file, and replaces the table in one
  transaction; cron runs it every 5 minutes. `verify` proves the key and
  role bounds by attempt. `docs/LAKE_SKELETON.md` "The staging lister".
