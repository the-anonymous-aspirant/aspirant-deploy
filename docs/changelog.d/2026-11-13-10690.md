- aspirant-server: a one-shot `server-migrate` service now runs AutoMigrate
  (`SERVER_MODE=migrate`, the same image) before `server` starts, and `server`
  skips it (`SKIP_AUTOMIGRATE=1`) (system_3 #9324-B1). Each has its own login
  switch in `.env`, the #9320 pattern: `ASPIRANT_SERVER_OWNER_DB_USER` /
  `_DB_LOGIN_PASSWORD` for the migration role, and `ASPIRANT_SERVER_DB_USER` /
  `_DB_LOGIN_PASSWORD` for the runtime role. Neither line is set, so both keep
  the admin pair and nothing changes at runtime until the go-live, #9324-C1.
  `server` no longer receives the other database passwords `.env` carries
  (the four services' and the migration role's): they are masked on it.
  Labels: `PGAPPNAME` `aspirant-server` and `aspirant-server-migrate`.
