- `lake-skeleton.sh` no longer puts a credential in any process's command line
  (system_3 #11381, after #11368). `env_set` wrote each value through
  `sed -i "s|^KEY=.*|KEY=$value|"`, so every key and password it wrote,
  including each one `explorer-env sync` copies into the deploy `.env`, was
  readable in `sed`'s argv. It now writes with bash builtins to a temp file
  beside the target and renames it, keeping the file's owner and mode. It also
  refuses a value containing a newline. A unit test shims every external
  command and asserts none of them sees the value.
- `explorer-env sync` deletes its backup of the deploy `.env` once its check
  passes, and removes any earlier one. It keeps the backup only when a sync
  fails part way. A standing copy of every served secret is no longer left on
  the scratch volume.
- The catalog role's SQL no longer prints the password when it fails. The
  session turns off the server's logging of failed statements, and psql's
  error is printed with the password redacted.
- New verb `rotate-explorer-ro` gives the explorer's catalog role a new
  password: generated in-process, set over psql's stdin, written to the
  skeleton env. `docs/LAKE_SKELETON.md` gives the one-sitting sequence with
  `explorer-env sync` and `explorer-decrypt-up`, and how to rotate the
  explorer's read-only Garage key.
