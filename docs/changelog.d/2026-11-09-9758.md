- Add the staging promotion runner, `scripts/lake_promote_staging.py` (system_3 #9758, #9546-A2).
  - **Why.** #9547 (not yet built) will land an uploaded file's bytes and a manifest under `bronze/staging/<upload_id>/` in the staging bucket through a write-only key that cannot read what it just wrote. Nothing reads that bucket back into the catalogued lake — this is that reader.
  - **What it does.** Lists every staged `upload_id`, re-verifies the manifest's claimed sha256 with a streamed read (the claim is untrusted — it is a network caller's claim, not an operator-typed manifest path), then promotes: `normal` via a server-side `copy_object` (the bytes never pass through this process), `high` via a streamed encrypt through `encrypt_for_storage_stream` into a `/scratch` spool and a single PUT. The `asset_inventory` row is written after the object lands and before the staged copy is deleted — the row is the commit marker, same ordering `lake_ingest.py` uses. One bad upload (a hash mismatch, a broken manifest) is recorded and stepped over; the run ends `partial`.
  - **Fail closed.** A pre-flight reads every staged manifest before touching an object; if any resolves to `sensitivity=high` and no KEK is loaded, the whole run refuses with a `failed` ledger row.
  - **Idempotent.** A re-run skips an already-catalogued digest and cleans up the leftover staged duplicate (the crash-between-row-and-delete case).
  - **New in `scripts/kek/envelope_store.py`:** `encrypt_for_storage_stream`, the streaming sibling of `encrypt_for_storage` — composes #9546-A1's `encrypt_object_stream` with DEK generation and wrapping, kept in this one sequencing module so the two writers cannot drift apart.
  - **Contract doc:** `docs/data-lake-design/STAGING_PROMOTION.md` — the staged-object key layout and the seven-field manifest schema, authoritative until #9547 builds against it.
  - **`lake-skeleton.sh promote [--dry-run]`**, mirroring `ingest`'s shape; the duckdb client container gains a `/scratch-spool` volume for the ciphertext spool and mounts for the new script.
  - **Security review (c63351) found and fixed three gaps before merge:**
    - **The `normal` path's TOCTOU.** `verify_staged_object`'s read and `copy_object` are two separate moments; anything that overwrote the staged object in between landed in bronze under the content address of the bytes it replaced. `promote_normal` now re-hashes the bronze COPY after `copy_object` and refuses (deleting the bad bronze object) on a mismatch — the uploader's key cannot write bronze, so that read is final.
    - **One bad upload could abort the whole run.** Several uncaught-exception paths (a missing staged object, a non-string `claimed_sha256`/`mime`, a negative `size_bytes`) crashed `promote()` before a ledger row was written, instead of being recorded as one failed upload. `read_manifest` now validates every field's type and format, and the per-upload promotion body is wrapped in a single broad exception guard that records the failure and continues.
    - **Sensitivity was trusted from the same writer whose digest is untrusted.** A manifest could declare `sensitivity: normal` for a `bucket: medical` upload and promote in the clear. The runner now keeps its own copy of #9547's bucket-to-sensitivity map and promotes under the STRICTER of the declared and mapped values.
  - **Tests.** `tests/lake_promote_staging_unit.sh`, two suites: host-side structural checks (imports the catalog and crypto contracts rather than re-deriving them; reuses `lake_ingest.py`'s `DuckDBCatalogStore`) and a `python:3.11-slim` + `cryptography==46.0.3 boto3==1.40.47 duckdb==1.5.4 moto` round-trip — normal and high promotion, a claimed-digest mismatch, the no-KEK refusal, an idempotent re-run, a direct catalog read proving a staged-but-unpromoted object has no row, a staged-object swap raced against `copy_object` (confirmed as a real negative control: fails without the destination re-hash, passes with it), malformed manifest fields, a missing staged object, and the sensitivity-map override. 65/65 green; also run live against the skeleton's real Garage (`lake-skeleton.sh promote --dry-run`, 0 staged uploads today — confirms reachability through the runner key's existing staging grant, no new provisioning needed).
