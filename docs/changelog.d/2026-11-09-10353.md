- Isolate `explorer-api` from the shared compose network (system_3 #10353, security review #8813 D1).
  - **Why.** `explorer-api` has no auth of its own ("No auth here on purpose" in `nginx/explorer.conf` — the gate is client-nginx's own `auth_request` in front of it) but sat on the shared compose network `default` alongside 14 other containers (advisor, browser, commander, histoire, monitor, ollama, penpot-frontend, postgres, server, tor, transcriber, translator, plus both client slots). Any of them could call `GET http://explorer-api:8000/api/assets/<sha>/content` with no login. Today that serves only metadata — decrypt-on-read is off — but the Gmail agent read path needs it on, and with a KEK loaded that read would be the operator's decrypted mail. A compromise or an SSRF in any neighbour (browser automation, tor, the LLM services) would then be enough to read the mailbox. The compose file already named this condition: "Re-derive it before … the explorer gets a decryption key." This is the structural half; the operator's half is the hold on #8813.
  - **What it does.** New `explorer_api` bridge, the penpot pattern applied the other way round (there, the frontend is dual-homed and its peers aren't; here, `explorer-api` itself is dual-homed since it has no peer of its own). `explorer-api` moves off `default` onto `{explorer_api, lake}`; `client-blue`/`client-green` (and `docker-compose.dev.yml`'s single `client`) gain `explorer_api` alongside `default`, since `default.conf`'s `set $upstream_explorer_api explorer-api:8000` only resolves on a network both containers share. No other service joins `explorer_api`. `lake` is untouched. Fixed in both `docker-compose.yml` and `docker-compose.dev.yml` — the dev file runs standalone, not as an overlay, so it needed the identical change independently or local dev would silently diverge from production's boundary.
  - **Not in scope** (per the task's own call): turning decrypt-on-read on, or giving the explorer a KEK. Both wait for the operator's answer on #8813.
  - **Companion PR:** aspirant-explorer adds the caller's address to the `asset_content`/`asset_messages` access-log lines, so a browser read (through client-nginx) and a host-side agent read (through this new bridge) can be told apart in the log, now that they can be told apart by network too.
  - **Tests.** New `tests/compose_network_scope_unit.sh`: `explorer-api`'s networks are exactly `{explorer_api, lake}` in every committed `docker-compose*.yml`, and no service outside `{explorer-api, client-blue, client-green, client}` joins `explorer_api` — checked against the static files, against three negative-control fixtures (still on `default`, missing `lake`, a neighbour joining `explorer_api`), and against the real resolved config (`docker compose config` with the `explorer`+`client` profiles enabled). Confirmed as a genuine negative control: reverting the real `docker-compose.yml` change makes the test fail exactly where expected.
