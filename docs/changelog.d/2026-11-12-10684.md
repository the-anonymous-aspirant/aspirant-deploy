- Postgres: `postgres`, `penpot-postgres` (`docker-compose.yml`), the lake
  skeleton's `catalog`, and the dev `postgres` now run with `init: true` and
  an exec-form `pg_isready` healthcheck (system_3 #10684, mirroring #10677).
  With the postmaster as PID 1, a probe that overran its timeout left
  `pg_isready` orphaned. The postmaster adopted it and, when it exited 2,
  treated it as a crashed backend, dropping every connection. That reset the
  system_3 database for about 7 s on 2026-11-12. Interval, timeout and retries
  are unchanged. `tests/compose_pg_healthcheck_unit.sh` keeps every
  `pg_isready` service this way. It takes effect only when each container is
  recreated.
