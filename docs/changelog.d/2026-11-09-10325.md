- `transcriber`, `commander`, `advisor` and `browser` each connect to Postgres with a fixed `application_name`, `PGAPPNAME: aspirant-<svc>`, set as a literal in both compose files (system_3 #9317-A5, #10325).
  - **Why:** a cut-over service that loses its two `.env` switch lines falls back to the superuser. With the label, `pg_stat_activity`, and security's sweep check (#10326), can tell that apart from server's own superuser sessions. Before this, every connection read `application_name = ''`.
  - **Why a literal:** a lost `.env` can't take the label with it.
  - **Drivers:** all four use libpq (`psycopg2-binary` 2.9.10, `psycopg[binary]` 3.2.3), and none sets `application_name` in code. A `docker exec -e PGAPPNAME` probe into the live transcriber and browser read it back.
  - **Tests:** `tests/compose_secret_scope_unit.sh` pins the literal. It adds a positive control, negative controls for an interpolated and a crossed label, and a resolved check before and after the switch.
  - The cutover runbook in `OPERATIONS.md` gains the `pg_stat_activity` check. Merging recreates the four services once.
