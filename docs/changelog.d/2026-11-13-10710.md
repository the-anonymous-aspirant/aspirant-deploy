- auto-pull: a new aspirant-server image now migrates as its own step before
  server is recreated (system_3 #9324-B2). `deploy_service` runs
  `docker compose run --rm --no-deps -T server-migrate` on the pulled image
  and recreates `server` with `--no-deps` only if it exits 0. A failed
  migration leaves the running server untouched, marks the image bad, and
  logs `failed_migrate` with the migrator's last line. Before this, `up`
  removed the old server before the migrator ran, so a failed migration
  took the site down.
