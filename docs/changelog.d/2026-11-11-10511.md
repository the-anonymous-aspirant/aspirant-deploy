- Mask five more names from `server` that aspirant-server's Go source never reads (system_3 #10511, from security's review of #10509's PR 126 — the same #9313 bleed, for the names that PR left out of scope).
  - **Why.** `server` keeps `env_file: .env` for `JWT_SECRET`/`BREAK_GLASS_TOKEN` (system_3 #9313's one exception), which also hands it `PENPOT_DB_PASSWORD`, `PENPOT_SECRET_KEY`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` and `REPORT_SEND_TOKEN`. Re-verified at the live server image revision (`af8944a`): `git grep -c <name> -- '*.go'` is 0 for every one of these, with `JWT_SECRET` (19 hits) as the positive control; no `aws-sdk-go`/`minio-go` import either, so no SDK picks `AWS_*` up implicitly.
  - **What it does.** Masks all five to `""` in `server`'s `environment:` block, mirroring the existing `SMTP_*` and lake-credential masks.
  - **Not in scope:** replacing `env_file: .env` with an explicit allow-list (the task's own "better alternative"). Bigger, riskier change — easy to omit a name the server genuinely needs and break production boot — for a `severity=low` finding whose exploitability already requires a code-execution or env-disclosure bug in `server` first. Left as a documented option, not built.
  - **Tests.** `tests/compose_secret_scope_unit.sh` (24/24, unrelated to this change — it checks `JWT_SECRET`/`BREAK_GLASS_TOKEN` scope, not these names), `compose_logging_unit.sh` (5/5), `changelog_unit.sh` (21/21). Verified by hand that `docker compose config` against the real `.env` resolves all five names to `""` on `server` while `JWT_SECRET` stays intact.
