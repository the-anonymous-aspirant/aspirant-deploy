- `transcriber`, `commander`, `advisor` and `browser` each read their database login from a per-service switch (system_3 #9317-A3, #9320).
  - **The switch:** `DB_USER` is `${ASPIRANT_<SVC>_DB_USER:-${DB_USER}}` and `DB_PASSWORD` is `${ASPIRANT_<SVC>_DB_LOGIN_PASSWORD:-${DB_PASSWORD}}`, in `docker-compose.yml` and `docker-compose.dev.yml`.
  - **No change on merge:** unset, the switch keeps today's admin pair, so nothing changes when this lands. `docker compose config` against the live `.env` resolves byte-identically before and after.
  - **Why not default to the roles:** `auto-pull.sh` runs compose from this checkout, so a role default would start a service as its role before `db-roles.sh move`, or fail compose while the role passwords are unset.
  - **Cutover and rollback:** setting a service's two lines in `.env` cuts it over, and deleting them rolls it back. `OPERATIONS.md` ("Per-service database roles") has the step-by-step for both.
  - **Tests:** `tests/compose_secret_scope_unit.sh` gains 10 checks. The static checks, in every compose file: each of the four has its own switch, no other service names the admin `DB_PASSWORD`, and no service names another's login. The resolved checks: with no switch set all four keep the admin pair, one switch moves one service, and with all four switched none holds the admin password. There are three negative controls.
