- Gave `server` a dedicated bind mount for copies of failed invoice-import uploads (system_3 #10563, the deploy half of #10536; security ruling c65222).
  - `/data/aspirant/import-failures` is mounted at `/data/import-failures` into `server` only, and `IMPORT_FAILURE_COPIES_DIR` points the server at it. The directory is a sibling of `files/` and `assets/`, not inside either, and is in no backup. The window is the server's 168-hour default (the operator's 7 days), shortenable from `.env`.
  - New `scripts/import-failures-backstop.sh`, run hourly from the `aspirant` crontab, deletes every file on the mount older than 168 hours by mtime, independent of the server's own sweep. A file it cannot delete, or a part of the tree it cannot read, exits 1 and is retried on the next run. It warns when the directory is not uid 1000 mode 0700.
  - New `tests/import_failures_unit.sh` pins the mount scope in every committed compose file, with negative controls, and the backstop's behaviour against a scratch directory.
  - The LUKS layer-1 playbook's one-off `restic backup /data` now excludes the directory, so the copies are not kept in a restic repository past their window.
